# 1 背景与目标​

南非电力公司 Eskom 供电不足时实行"分区停电"(load shedding):全国按区块轮流断电,等级为 Stage 1~8,等级越高停电时段越多。我们的储能产品需要在停电前自动把用户电池充满(强冲),并推送停电通知,数据源是第三方服务 sepush(EskomSePush Business API)。​

sepush 官方将下线 2.x、升级到 3.0,接口语义有破坏性变化:原 `/area` 不再返回停电计划,计划迁移到新增的 `/schedule` 端点;区域 id 与时刻表 id 拆成两套概念。本次把 roulette 定时任务(eskominfoJob 入库 / eskomPushMessageJob 推送)升级到 3.0。​

**升级原则**:业务行为不变;数据库格式不变;下游 rice(APP 展示接口)零改动;不做数据迁移。​

## 3.2 核心转换逻辑​

- •旧库 block_id 是 v2 格式(如 eskde-10-fourways),取前两段得到 3.0 schedule id(eskde-10)后直接调 /schedule 获取停电计划。​
- •3.0 返回的时段是带时区偏移的完整时间戳,转换器统一转回老格式入库:固定 8 级二维数组,每级为 "HH:mm-HH:mm" 时间段,允许跨天(如 20:00-00:30),且每级恒包含前面所有级的并集(不依赖上游是否已累加)。任何数据非法(时间戳错、日期不符、等级越界)则拒绝整份响应,保留旧数据。​

## 3.3 入库链路​

eskominfoJob:查 plants 的 block_id → 按 schedule id 分组(实测 273 个 block 归并为 72 个 schedule,每轮只请求 72 次)→ 调 /schedule → 转换 → 回填所有原 block_id 入库。发布时序由 XXL-JOB 控制:发布后保持 eskominfoJob 停用,验收通过再恢复调度。​

## 3.4 addregion 硬禁用​

addregion 是手动执行的区域初始化 job,依赖 areas_search 的 region 字段(3.0 已删除),重跑会写入新格式 id 污染存量数据。本次对 job 入口和 service 方法双重硬禁用(直接抛异常),存量 ns_region 数据继续使用。​

## 5.1 block_id 从哪来​

库里 `plants.block_id`(v2 格式,如 eskde-10-fourways)是用户注册电站时,从 APP 的南非省市区树里选出来的自己所在区块;而树里的区块 id,是 addregion 当年从 sepush 2.x 的 areas_search 同步进 ns_region 的。它是用户侧历史数据,分布在 plants 和 ns_region 两张表,下游 rice 按它做等值 JOIN——所以升级只能代码内转换、不动库。​

## 5.2 老格式的跨天处理(2.0 时代)​

老格式 "HH:mm-HH:mm" 是纯时间、没有日期,跨天无法显式表达,靠 begin 大于 end 隐式表达(如 20:00-00:30)。下游两端都有专门分支:rice 展示时拆成当天 20:00-23:59 + 次日 00:00-00:30;roulette 强充下发时把恢复任务排到次日。​

跨两天:老格式在结构上无法表达(只有两个时间点、无日期)。已用全量数据验证(70/72 个 schedule、9535 个槽):当天内 8499 个、跨到次日 1036 个、跨两天及以上 0 个——Eskom 的停电槽都是当天固定时段,最晚结束于次日凌晨 00:30,调度体系里不存在连续停电超过一天的槽。3.0 转换器校验"end 只能落在当天或次日",超出即拒收,与真实数据完全吻合。​

## 5.3 addregion 的用途与禁用原因​

addregion 是手动执行的一次性区域初始化 job:从 eskom 官网遗留接口拿市/郊区列表,再用 areas_search 反查 sepush 区块 id 写入 ns_region。它依赖 areas_search 的 region 字段做城市匹配,而 3.0 已删除该字段、id 也变成新格式——重跑会 NPE 或写入与存量 v2 格式不一致的数据,污染 ns_region(APP 地区树和推送地址都依赖它)。日常链路不经过 addregion,所以直接硬禁用,存量数据继续使用。​

## 5.4 其他存量行为备注​

代码里 Cape Town(areaId=342)的"特殊处理"实际读取的是 status.eskom(变量名 capetown 有误导),与国家级推送用的是同一份数据;且 areaId=342 的 SQL 过滤在存量数据(非空 block_id 全为两段以上格式)下匹配不到任何行。该行为是存量现状,本次升级不改动。另:存量 1621 是电站行数,去重后为 273 个 distinct block_id,再归并为 72 个 schedule id,统计口径不要混用。​
