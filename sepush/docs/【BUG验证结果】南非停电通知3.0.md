## 4. 待修复后回归：通过后可直接粘贴

### #3672 恢复任务 Cron 时区错误

现有结论：缺陷已稳定复现，不能按“已修复”直接关闭。最近一次保留现场中，APP 最后一段停电于南非 21:30 结束，但恢复任务 `triggerNextTime` 对应南非 15:30，实际提前 6 小时。

复测检查点：

- APP 最后一段停电结束时间与 XXL 恢复任务的实际执行时间必须对应同一个绝对时刻；
- 必须核对 `triggerNextTime`，不能只比较 Cron 表面的小时和分钟；
- 恢复任务到点执行后，APP 原有 Mode Scheduler 能正常恢复。

回归通过后禅道用语：

> 测试环境回归通过。构造南非电站停电计划并触发强充后，APP 展示的最后一段停电结束时间与 XXL 恢复任务 triggerNextTime 对应同一个绝对时刻，不再提前或延后 6 小时；恢复任务执行成功，客户原有 Mode Scheduler 正常恢复。时区配置及恢复链路结果符合预期，同意关闭 BUG。

### #3673 空 plantId 未拦截

现有结论：缺陷复现日志 258195 显示 `plantId` 为空时命中 4367 台设备；无修复后的拦截验证记录，不能直接关闭。

复测检查点：

- 使用空 `executorParam` 手动触发 `removeDeviceController`；
- Handler 应立即返回参数错误；
- 日志中设备查询数和操作数均应为 0；
- 再使用明确的测试 `plant_id` 验证合法场景仍只恢复目标电站。

回归通过后禅道用语：

> 测试环境回归通过。手动触发 removeDeviceController 并传入空 executorParam 后，Handler 立即返回参数错误，未查询、未命中、未操作任何设备；使用明确测试 plant_id 再次触发时，仅命中并恢复目标电站设备。空参数扩大设备范围的问题已修复，同意关闭 BUG。

### #3689 Cape Town 分支错误读取国家级 Stage

现有结论：Mock 中 `eskom.next_stages` 有 Stage、`capetown.next_stages` 为空时，旧逻辑仍进入 Cape Town 分支并重复创建恢复任务；无修复回归记录，不能直接关闭。

复测检查点：

- Mock 设置 `eskom.next_stages` 为单个 Stage 4，`capetown.next_stages=[]`；
- 只允许国家级 Eskom 分支处理一次；
- Cape Town 分支不得复用 Eskom Stage；
- 不得重复通知、重复强充或先后创建两个恢复任务。

回归通过后禅道用语：

> 测试环境回归通过。Mock 设置 eskom.next_stages 为单个 Stage 4、capetown.next_stages 为空后，系统仅执行一次 Eskom 国家级处理，Cape Town 分支未复用国家级 Stage；未出现重复通知、重复强充或重复创建恢复任务。分支取值符合 3.0 status 结构预期，同意关闭 BUG。

### #3690 设备恢复链路失败保护与状态一致性不足

现有结论：历史执行中出现单设备恢复耗时 15 分 22 秒、回调成功但 APP 设置未同步恢复，以及提前手动恢复后数据库记录仍显示未恢复；代码检查还发现设备写入失败后可能继续删除 Redis 备份。当前没有覆盖完整失败分支的修复回归，不能直接关闭。

复测检查点：

- 正常恢复时，任务应在合理时间内完成，APP 原有计划恢复，数据库恢复状态同步成功；
- 模拟设备 `settingSet()` 失败时，任务必须返回失败并保留 Redis 备份，不得写成恢复成功；
- 失败后重试成功时，设备设置、数据库状态和 Redis 备份清理结果必须一致；
- 日志应能明确定位成功数、失败数及失败原因。

回归通过后禅道用语：

> 测试环境回归通过。正常恢复场景下，removeDeviceController 在合理时间内执行完成，APP 原有 Mode Scheduler 已恢复，数据库恢复状态同步成功；模拟设备设置写入失败时，任务正确返回失败并保留 Redis 备份，未误标记成功；再次重试成功后设备设置、数据库状态和备份清理结果一致，日志可明确查看成功数、失败数和失败原因。恢复链路失败保护及状态一致性符合预期，同意关闭 BUG。
